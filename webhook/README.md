# سیستم Webhook برای رصد تراکنش‌های بلاکچین

این ماژول برای رصد تراکنش‌های اسمارت کانترکت‌ها و آدرس‌های کیف پول طراحی شده است.

## نحوه کارکرد

1. **ایجاد سابسکریپشن**: برای هر اسمارت کانترکت یا آدرس کیف پول، یک سابسکریپشن در Tatum ایجاد می‌شود.
2. **دریافت اعلان‌ها**: Tatum هر تراکنش مرتبط را به webhook ما ارسال می‌کند.
3. **پردازش تراکنش‌ها**: تراکنش‌ها بررسی می‌شوند تا مشخص شود به کاربران ما مربوط هستند یا خیر.
4. **ذخیره‌سازی و اعلان**: تراکنش‌های مرتبط در دیتابیس ذخیره شده و به فرانت‌اند اعلام می‌شوند.

## تشخیص تراکنش‌های مرتبط با کاربران

سیستم به دو روش تشخیص می‌دهد که آیا یک تراکنش به کاربران ما مربوط است یا خیر:

### 1. برای تراکنش‌های اسمارت کانترکت (CONTRACT_LOG_EVENT):

1. ابتدا تمام آدرس‌های کیف پول کاربران از جدول `Address` دریافت می‌شود.
2. سپس برای هر رویداد لاگ در تراکنش، بررسی می‌شود که آیا هر یک از این آدرس‌ها در داده‌ها یا موضوعات (topics) لاگ وجود دارد.
3. اگر آدرسی پیدا شد، تراکنش به عنوان «مرتبط» علامت‌گذاری می‌شود.

### 2. برای تراکنش‌های مستقیم (ADDRESS_TRANSACTION):

1. آدرس‌های فرستنده (`from`) و گیرنده (`to`) تراکنش با آدرس‌های کاربران مقایسه می‌شوند.
2. اگر آدرس فرستنده یکی از آدرس‌های کاربران باشد، تراکنش با جهت `outbound` ثبت می‌شود.
3. اگر آدرس گیرنده یکی از آدرس‌های کاربران باشد، تراکنش با جهت `inbound` ثبت می‌شود.

## ذخیره‌سازی تراکنش‌ها در پایگاه داده

تراکنش‌های مرتبط با کاربران در جدول `Transfers` ذخیره می‌شوند. مراحل ذخیره‌سازی به شرح زیر است:

1. ابتدا شناسه بلاکچین (`BlockchainID`) بر اساس نماد بلاکچین (ETH, BSC, ...) از جدول `Blockchains` دریافت می‌شود.
2. سپس اطلاعات تکمیلی تراکنش مانند شماره بلاک، timestamp، و... از داده‌های webhook استخراج می‌شود.
3. تعیین می‌شود که آیا تراکنش مربوط به توکن است یا ارز اصلی بلاکچین (`native` یا `token`).
4. لینک مرورگر بلاکچین بر اساس نوع بلاکچین ایجاد می‌شود.
5. برای هر آدرس مرتبط، یک رکورد جدید در جدول `Transfers` ایجاد می‌شود با فیلدهای زیر:
   - `BlockchainID`: شناسه بلاکچین
   - `AddressID`: شناسه آدرس کاربر
   - `WalletID`: شناسه کیف پول
   - `TxHash`: هش تراکنش
   - `BlockNumber`: شماره بلاک
   - `Timestamp`: زمان تراکنش
   - `FromAddress`: آدرس فرستنده
   - `ToAddress`: آدرس گیرنده
   - `Amount`: مقدار تراکنش
   - `TokenSymbol`: نماد توکن (در صورت وجود)
   - `TokenContract`: آدرس قرارداد توکن (در صورت وجود)
   - `AssetType`: نوع دارایی (`native` یا `token`)
   - `Direction`: جهت تراکنش (`inbound` یا `outbound`)
   - `Status`: وضعیت تراکنش (`confirmed`)
   - `IsSuccessful`: موفقیت‌آمیز بودن تراکنش
   - `ExplorerUrl`: لینک مرورگر بلاکچین
   - `CreatedAt`: زمان ایجاد رکورد

## سابسکریپشن‌های گروهی (Batch Subscriptions)

برای بهینه‌سازی تعداد سابسکریپشن‌ها، سیستم امکان ایجاد سابسکریپشن‌های گروهی را فراهم می‌کند:

1. **دسته‌بندی آدرس‌ها بر اساس بلاکچین**: آدرس‌های کاربران بر اساس بلاکچین مربوطه دسته‌بندی می‌شوند.
2. **ایجاد سابسکریپشن‌های 50 تایی**: هر بلاکچین می‌تواند چندین سابسکریپشن داشته باشد، که هر کدام حداکثر 50 آدرس را پوشش می‌دهند.
3. **کاهش هزینه‌ها**: به جای ایجاد صدها یا هزاران سابسکریپشن تکی، تعداد کمتری سابسکریپشن گروهی ایجاد می‌شود.

### مزایای استفاده از سابسکریپشن‌های گروهی:

- **کاهش تعداد سابسکریپشن‌ها**: به جای یک سابسکریپشن برای هر آدرس، سابسکریپشن‌های گروهی ایجاد می‌شوند.
- **مدیریت آسان‌تر**: تعداد کمتر سابسکریپشن، مدیریت سیستم را آسان‌تر می‌کند.
- **صرفه‌جویی در هزینه‌ها**: برخی سرویس‌ها برای هر سابسکریپشن هزینه دریافت می‌کنند.
- **افزایش کارایی**: کاهش تعداد درخواست‌ها به API باعث افزایش کارایی سیستم می‌شود.

### روش عملکرد سابسکریپشن‌های گروهی:

وقتی یک تراکنش به یکی از آدرس‌های موجود در یک سابسکریپشن گروهی ارسال می‌شود، Tatum آن را به webhook ما ارسال می‌کند. سپس سیستم، همانند سابسکریپشن‌های تکی، آن را پردازش کرده و در صورت مرتبط بودن، در دیتابیس ذخیره می‌کند و به‌روزرسانی موجودی را انجام می‌دهد.

## راه‌اندازی

1. مطمئن شوید که `TATUM_API_KEY` در فایل `.env` یا متغیرهای محیطی تنظیم شده است.
2. متغیر `WEBHOOK_BASE_URL` در `config.py` یا متغیرهای محیطی به آدرس عمومی API خود تنظیم کنید.
3. متغیر `DATABASE_URL` برای اتصال به پایگاه داده در فایل `config/__init__.py` تنظیم شده است.
4. مسیر `/webhook/tatum/transaction` در وب‌سرور شما باید قابل دسترسی از اینترنت باشد.

## نحوه استفاده

### راه‌اندازی سریع با اسکریپت خودکار

برای راه‌اندازی سریع سابسکریپشن‌های گروهی برای تمام آدرس‌های کاربران، می‌توانید از اسکریپت `setup_batch_webhooks.py` استفاده کنید:

```bash
# اجرای اسکریپت راه‌اندازی خودکار
python webhook/setup_batch_webhooks.py
```

این اسکریپت:
1. تمام آدرس‌های کاربران را از دیتابیس دریافت می‌کند
2. آنها را بر اساس بلاکچین دسته‌بندی می‌کند
3. برای هر دسته، سابسکریپشن‌های گروهی (حداکثر 50 آدرس در هر گروه) ایجاد می‌کند
4. نتایج را در فایل `batch_subscriptions.json` ذخیره می‌کند

### از طریق خط فرمان

برای مدیریت سابسکریپشن‌ها می‌توانید از فایل `webhook_manager.py` استفاده کنید:

```bash
# لیست تمام سابسکریپشن‌های فعال
python webhook_manager.py list

# ایجاد سابسکریپشن برای یک اسمارت کانترکت
python webhook_manager.py create --type contract --address 0xContractAddress --chain ETH

# ایجاد سابسکریپشن برای یک آدرس کیف پول
python webhook_manager.py create --type address --address 0xWalletAddress --chain ETH

# ایجاد چندین سابسکریپشن از فایل JSON
python webhook_manager.py batch webhook/contract_subscriptions.json --verbose

# ایجاد سابسکریپشن‌های گروهی برای آدرس‌های کاربران
python webhook_manager.py batch-addresses --verbose

# حذف یک سابسکریپشن
python webhook_manager.py delete subscription_id
```

### از طریق کد

```python
from webhook import create_contract_subscription, list_subscriptions, delete_subscription
from webhook.tatum_subscription import create_batched_blockchain_subscriptions
from webhook.webhook_handler import get_user_addresses_from_db

# ایجاد سابسکریپشن برای اسمارت کانترکت
result = create_contract_subscription(
    contract_address="0xContractAddress",
    chain="ETH"
)

# لیست تمام سابسکریپشن‌های فعال
subscriptions = list_subscriptions()

# حذف یک سابسکریپشن
success = delete_subscription("subscription_id")

# ایجاد سابسکریپشن‌های گروهی برای تمام آدرس‌های کاربران
user_addresses = get_user_addresses_from_db()
results = create_batched_blockchain_subscriptions(user_addresses)
```

## فایل نمونه سابسکریپشن‌ها

یک فایل JSON نمونه با سابسکریپشن‌های رایج برای توکن‌های اصلی در مسیر `webhook/contract_subscriptions.json` قرار داده شده است. 
می‌توانید این فایل را به عنوان یک شروع برای ایجاد چندین سابسکریپشن به صورت همزمان استفاده کنید.

## ادغام با برنامه Flask

این ماژول به صورت خودکار یک blueprint Flask به نام `webhook_bp` ایجاد می‌کند که در مسیر `/webhook` قرار می‌گیرد.
برای ادغام با برنامه Flask اصلی خود، کافی است تابع `init_app` را فراخوانی کنید:

```python
from webhook import init_app as init_webhook

def create_app():
    app = Flask(__name__)
    # ... کد موجود ...
    init_webhook(app)
    # ... کد موجود ...
    return app
```

## به‌روزرسانی موجودی کیف پول

پس از شناسایی و ذخیره تراکنش‌ها، سیستم تابع `update_wallet_balance` را فراخوانی می‌کند. این تابع:

1. آخرین تراکنش مرتبط با آدرس را از جدول `Transfers` پیدا می‌کند
2. اطلاعات توکن را از دیتابیس دریافت می‌کند (برای تراکنش‌های توکن)
3. از `BalanceService` برای به‌روزرسانی `UserHolding` استفاده می‌کند
4. تراکنش‌هایی که زمان آن‌ها قبل از `UpdatedAt` کاربر باشد، نادیده گرفته می‌شوند

## اعلان به فرانت‌اند

برای اعلان تراکنش‌های جدید به فرانت‌اند، می‌توان از یکی از روش‌های زیر استفاده کرد:

1. **WebSocket**: برای آپدیت لحظه‌ای UI
2. **Firebase Cloud Messaging (FCM)**: برای ارسال نوتیفیکیشن به دستگاه‌های موبایل
3. **Server-Sent Events (SSE)**: برای ارسال رویدادها از سرور به مرورگر

## گسترش سیستم

برای اضافه کردن منطق سفارشی برای پردازش تراکنش‌ها، می‌توانید توابع زیر را در فایل `webhook/webhook_handler.py` تغییر دهید:

- `process_contract_log_events`: برای پردازش رویدادهای اسمارت کانترکت
- `process_address_transaction`: برای پردازش تراکنش‌های آدرس کیف پول
- `update_wallet_balance`: برای به‌روزرسانی موجودی کیف پول
- `notify_frontend`: برای ارسال اعلان به فرانت‌اند 

# Coinceeper Webhook System

سیستم وب‌هوک برای پروژه Coinceeper که به موارد زیر امکان می‌دهد:
1. ارسال اعلان برای رویدادهای قرارداد‌های هوشمند
2. ارسال اعلان برای تراکنش‌های آدرس‌های کیف پول
3. ثبت تراکنش‌های مرتبط با کاربران در پایگاه داده
4. به‌روزرسانی موجودی کیف پول‌ها بر اساس تراکنش‌های دریافتی

## تغییرات اخیر

- **بهبود سازگاری با تاتوم**: فرمت آدرس‌های بلاکچین اصلاح شده و نام‌های بلاکچین استاندارد شده‌اند.
- **آدرس وب‌هوک کوتاه‌تر**: آدرس وب‌هوک به فرمت کوتاه‌تر تغییر کرده است تا با محدودیت‌های تاتوم سازگار باشد.
- **اعتبارسنجی آدرس‌ها**: اعتبارسنجی آدرس‌ها برای هر بلاکچین اضافه شده است.

## نصب و راه‌اندازی

1. اطمینان حاصل کنید که تمام وابستگی‌ها نصب شده‌اند:
   ```
   pip install -r requirements.txt
   ```

2. متغیرهای محیطی را در فایل `.env` تنظیم کنید:
   ```
   TATUM_API_KEY=your_tatum_api_key
   WEBHOOK_BASE_URL=https://your-server-domain.com
   DATABASE_URL=mysql+pymysql://username:password@localhost/dbname
   ```

3. اجرای اسکریپت راه‌اندازی وب‌هوک‌های گروهی:
   ```
   python webhook/setup_batch_webhooks.py
   ```

## مسیر‌های API

- **POST /webhook/tatum/transaction** - نقطه پایانی برای دریافت وب‌هوک‌های تاتوم
- **GET /webhook/test** - نقطه پایانی تست برای اطمینان از کارکرد صحیح سیستم وب‌هوک

## ساختار کد

- **webhook_handler.py** - پردازش درخواست‌های وب‌هوک و ذخیره تراکنش‌ها در پایگاه داده
- **tatum_subscription.py** - مدیریت اشتراک‌ها با تاتوم و گروه‌بندی آدرس‌ها
- **setup_batch_webhooks.py** - راه‌اندازی خودکار اشتراک‌های گروهی برای آدرس‌های کاربران

## نکات مهم و راهنمایی عیب‌یابی

### مشکلات رایج:

1. **خطای اعتبارسنجی آدرس**: اطمینان حاصل کنید که آدرس‌های شما با فرمت صحیح برای هر بلاکچین تنظیم شده‌اند:
   - ETH/BSC/MATIC: باید با '0x' شروع شوند و 42 کاراکتر داشته باشند
   - BTC: باید با '1'، '3' یا 'bc1' شروع شوند
   - XRP: باید با 'r' شروع شوند
   - TRX: باید با 'T' شروع شوند
   - SOL: باید در فرمت base58 باشند

2. **خطای "Invalid format of URL provided"**: اطمینان حاصل کنید که:
   - متغیر محیطی `WEBHOOK_BASE_URL` به درستی تنظیم شده است
   - سرور شما از HTTPS استفاده می‌کند
   - مسیر وب‌هوک صحیح است (از `/webhook/tatum/transaction` استفاده کنید)

3. **مشکلات نام بلاکچین**: اطمینان حاصل کنید که از نام‌های بلاکچین استاندارد استفاده می‌کنید:
   - از `ethereum-mainnet` به جای `ETH`
   - از `bsc-mainnet` به جای `BSC` یا `BNB`
   - از `polygon-mainnet` به جای `MATIC`
   - و غیره

### تست وب‌هوک:

برای تست وب‌هوک می‌توانید از دستور cURL استفاده کنید:

```bash
curl -X POST https://your-server-domain.com/webhook/tatum/transaction -H "Content-Type: application/json" -d '{"type":"ADDRESS_TRANSACTION","chain":"ETH","transactionId":"0x123"}'
```

پاسخ باید به این صورت باشد:

```json
{"status":"received"}
```

## بهینه‌سازی عملکرد

1. **اشتراک‌های گروهی**: برای کاهش تعداد اشتراک‌ها، آدرس‌ها را در گروه‌های 50 تایی ارسال کنید.
2. **بررسی زمان تراکنش‌ها**: فقط تراکنش‌هایی که بعد از آخرین به‌روزرسانی کاربر انجام شده‌اند ذخیره می‌شوند.
3. **احراز هویت**: اضافه کردن احراز هویت به وب‌هوک برای افزایش امنیت.
